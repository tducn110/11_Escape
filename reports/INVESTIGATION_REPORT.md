## Level Architecture Analysis

### File Roles
- `src/features/tribe-out/TribeOutGame.tsx`: The main game UI component, rendering the board and HUD.
- `src/features/tribe-out/gameLogic.ts`: Core rules, state updates, validation, rotate, exit logic.
- `src/features/tribe-out/types.ts`: TypeScript definitions for the levels, entities (unit, gate, switch, obstacle).
- `src/features/tribe-out/levels.ts`: Contains the `LEVELS` array (the source of truth), containing 100 levels.
- `src/features/tribe-out/TribeOutBoard.tsx`: Renders the game board cells based on the layout matrix.
- `src/features/tribe-out/TribeOutEntity.tsx`: Renders the individual puzzle entities using PIXI/GSAP.
- `src/features/tribe-out/isometric.ts`: Handles coordinate translation from board space to isometric screen space.
- `scripts/handcrafted_levels.cjs` / `scripts/gen_levels.cjs`: **DO NOT EXIST**. Have been replaced by `scripts/levels/cli/generate.ts` and `scripts/levels/catalog.ts`.

### Level Data Source
- `IS_GENERATED`: **Yes** (Generated by `generate.ts` and stored in `levels.ts`).
- `GENERATOR_EXISTS`: **Yes** (`scripts/levels/catalog/builder.ts` handles procedural generation based on seeds and phases).
- `SOURCE_OF_TRUTH`: The generator scripts define the phase bands, but `levels.ts` holds the final deployed set. Generation is deterministic based on generator version `recovery-v3` but contains a fallback mechanism.

## Runtime Flow Analysis
- Start Screen to Level 1: `TribeOutGame` loads the level via `levelIndex`.
- Next Level Loading: Dispatches `NEXT_LEVEL` action which increments `levelIndex` and resets the puzzle state based on the new level from `levels.ts`.
- End of Game: Occurs when `levelIndex` exceeds the number of levels.
- How states are tracked: Local state via `useReducer` in `TribeOutGame.tsx` combined with `gameLogic.ts`.

## Initial Diagnostic (Difficulty and Mechanics)
- **Number of levels**: 100
- **Progression Type**: Divided into 5 Phases (Phase 1: 1-20, Phase 2: 21-40, Phase 3: 41-60, Phase 4: 61-80, Phase 5: 81-100).
- **Core issue discovered**: The `difficulty.csv` generated by the analyzer reveals that for **ALL 100 levels**, `minRotateRequired` is `0`. While the generator `builder.ts` assigns `rotateCharges` to levels and claims to create "Trapped Units" (`addTrappedUnit`), the puzzle solver verifies that all levels can be solved without EVER rotating a unit. This strongly suggests the rotate mechanic is rendered functionally useless by the generator's geometry.
- **Pacing**: `initialAvailableMoves` is almost uniformly `2` across all phases. `unitCount` slowly scales from 2 to 11.
